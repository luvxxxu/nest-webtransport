# Security policy

Security fixes target the latest released version. Read `docs/security.md` for admission timing,
resource limits, cancellation and deployment boundaries before exposing a server.

Report suspected vulnerabilities privately through GitHub's private vulnerability reporting for
this repository when available. Otherwise contact the maintainer through the contact channel on
their GitHub profile to arrange private disclosure. Do not put credentials, exploitable details,
or user data in a public issue.

Include the affected package/version, runtime/platform, minimal reproduction, expected/observed
behavior, and impact. Use a local test environment for reproductions. A release will include a
regression test and changelog entry for confirmed fixes where disclosure permits it.
